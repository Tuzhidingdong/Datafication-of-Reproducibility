# V0.1 architecture

## Locked decisions

| Decision | Selected design |
|---|---|
| Skill platform | Antigravity Workspace Skill |
| Execution | Hybrid: local Python plus targeted Agent reasoning |
| Automation | Guided, with explicit scientific approval gates |
| Source-data policy | Preserve: immutable source files; derived outputs in separate run directories |
| Writing integration | Every completed research package includes a human-readable guide and machine-readable manifest for a downstream Writing Skill |

## Components

### Antigravity Supervisor

Owns project orchestration, phase state, user approvals, task dispatch, and synthesis. It should not perform large numerical computations in its context.

### Existing OpenCode Worker Manager

Reuse the user's existing manager and routing. This repository defines task/result contracts but does not introduce a replacement manager or assume a particular MCP tool name.

### Local Python research engine

Performs deterministic inspection, transformation, statistics, model fitting, validation, plotting, and report-data generation. Scripts must accept explicit inputs and outputs and must not mutate source files.

### Domain adapter

Defines domain-specific entity types, field mappings, units, outcome semantics, experimental protocols, and mechanism vocabulary. The zinc-battery adapter is provisional until the actual CSV and JSON are inspected.

### Scientific record and publication output

Stores immutable run facts and creates a publication-ready package whose claims, models, tables, and figures have traceable provenance.

## Separation of responsibilities

- Scientific choices are made by the Supervisor with user approval at defined gates.
- Semantic interpretation and critical scientific review may be delegated to Workers.
- Deterministic numeric outputs come from Python artifacts, not Worker prose.
- Source evidence remains linked to observations.
- Manuscript prose is derived from structured records.

## Workspace layout

The project checkout contains the Skill at .agents/skills/datafication-of-reproducibility/SKILL.md, the runtime, references, schemas, templates, tests, and domain profiles. User datasets and run outputs remain outside version-controlled source unless explicitly intended for publication.

## Runtime boundaries

The runtime should initially use a small dependency surface. Prefer Python standard library for file inspection and metadata tasks. Add Pandas/scikit-learn/CatBoost or other packages only when the corresponding modelling stage is implemented and approved. Do not add graph databases, distributed compute, or deep-learning frameworks without demonstrated need.

## Cache policy

Cache keys must incorporate input file SHA-256, project/domain configuration hash, script or package version, relevant dependency/environment identity, analysis parameters, and random seed. A cache hit is reusable only if all relevant inputs match. A changed source, configuration, code version, or environment invalidates the affected downstream artifacts, not necessarily the entire project.

## Versioning

Use explicit schema versions for project configs, task packets, result records, and publication manifests. A schema change must include a migration or compatibility note. Do not silently reinterpret existing outputs.
