# V0.4 — Pairwise predictive interaction discovery

## Scope and scientific question

The initial V0.4 implementation screens pairwise interactions for numeric endpoints. It asks whether adding encoded product terms for one feature pair improves prediction on Studies not used for candidate selection or fitting, compared with an additive Ridge model.

It does not claim that a non-additive predictive relationship is causal, synergistic, or a physical mechanism. It does not provide an inferential p-value or universal interaction-strength statistic. Categorical endpoints require a separately validated interaction contract and are rejected by this implementation.

## Interaction definition

Each reviewed feature binding is encoded using the deterministic modeling encoder: numeric features are standardized using the current fitting partition; categorical features are one-hot encoded using levels observed in that fitting partition.

For candidate features A and B, the interaction-augmented design appends all products between their encoded columns. Numeric × numeric adds one bilinear term; numeric × categorical adds one term per observed category; categorical × categorical adds products for category pairs. The encoder and standardizer are fitted only on the relevant training Studies.

For each pair, the screen compares:
- Additive model: Ridge on the original encoded features.
- Pair-augmented model: Ridge on the original encoded features plus products for this one feature pair.

The pair is evaluated separately from other pairs. This is a marginal pairwise screen, not a jointly fitted all-interactions model and not a decomposition of unique causal contributions.

## Nested Study-held-out protocol

The outer folds are grouped by canonical Study ID. Every Study is held out once. In each outer fold:

1. Outer test Studies are removed from all fitting and inner selection.
2. Remaining Studies are split into inner training and inner validation groups using the deterministic seed-based procedure.
3. The additive model chooses its Ridge penalty from inner validation RMSE.
4. Each pair-augmented model independently chooses its Ridge penalty from that same inner validation partition.
5. Additive and pair-augmented models are refitted on all outer-training Studies and compared on the same held-out Studies.

The primary statistic is:

    RMSE improvement = RMSE(additive) - RMSE(pair-augmented)

A positive value means that the pair-augmented model made a lower held-out RMSE on that fold. No held-out test result is used to choose a penalty or declare a pair before the outer comparison.

## Joint support and candidate settings

Optional settings in modeling_task.json:

~~~json
{
  "interaction_discovery": {
    "feature_pairs": [
      {"feature_a": "variable_A", "feature_b": "variable_B"}
    ],
    "minimum_joint_observations": 10,
    "minimum_joint_studies": 3,
    "minimum_positive_fold_fraction": 0.6,
    "maximum_feature_pairs": 100,
    "maximum_interaction_columns": 500
  }
}
~~~

If feature_pairs is omitted, all unordered pairs among explicit task feature bindings are screened, subject to maximum_feature_pairs. If supplied, each pair must reference two distinct feature IDs in the task. Pair generation is bounded; high-dimensional product encodings above the declared cap are not silently truncated.

Joint coverage records Observation count, canonical Study count, distinct observed value pairs, and observed levels for each feature. Candidates below the minimum joint observation or Study support are excluded before fitting.

A pair is labelled CROSS_STUDY_PREDICTIVE_INTERACTION_CANDIDATE only when its mean outer-fold RMSE improvement is positive and the fraction of outer folds with positive improvement meets the task threshold. The report also retains each fold's result and each held-out Study's MAE improvement. These thresholds are screening rules, not statistical significance tests.

## Interpretation and robustness safeguards

- A positive predictive increment is evidence that this pair's product basis helps prediction under this cohort, endpoint, encoding, and validation design.
- It does not show that the factors physically interact, that one factor modifies the causal effect of another, or that the pair is synergistic.
- A feature pair concentrated in a subset of Studies may be confounded by laboratory, protocol, material family, or hidden study-level factors. Study grouping alone does not solve these issues.
- A pair can improve some held-out Studies and harm others. Preserve fold-level and Study-level counterexamples; do not report only the mean.
- Screening many pairs creates a multiple-comparison problem. This initial screen does not calculate inferential p-values or FDR-adjusted significance. Candidate labels are predictive screening labels only.
- The product basis captures bilinear interactions in the selected encoding. It does not comprehensively detect arbitrary nonlinear or threshold interactions.
- Interactions are not fit for categorical outcomes in this increment.
- Mechanistic interpretation requires independent experimental, theoretical, or computational evidence and must follow the mechanism-evidence contract.

## Command

After G2 approval and cohort review:

~~~bash
dor discover-interactions --cohort-dir 04_modeling/cohort --task modeling_task.json --out-dir 04_modeling/interactions
~~~

Optional: --folds 5 --seed 42. The command requires at least four eligible Studies, a numeric endpoint, and at least one candidate pair meeting the declared joint-support thresholds. Cohort and task inputs remain read-only; the output directory must be new or empty.

## Output artifacts

- interaction_discovery_report.json: method/statistic definition, fold protocol, support, pair-level results, thresholds, exclusions, interpretation limits, and candidate labels.
- interaction_catalogue.csv: compact pair-level Interaction Catalogue for review and later plotting.
- interaction_oof_predictions.csv: additive and pair-augmented held-out predictions for each Observation/pair/fold, enabling counterexample and error analysis.
- interaction_discovery_manifest.json: task/cohort hashes, output hashes, seed, fold count, and explicit claim scope.

Schemas: schemas/interaction_discovery_report.schema.json and schemas/interaction_discovery_manifest.schema.json.

## Engineering acceptance and limits

Synthetic tests cover a deliberately bilinear cross-Study signal, exact outer/inner Study separation, repeatability, categorical endpoint rejection, support thresholds, invalid pair IDs, candidate-count caps, input immutability, and output-directory protection. This is software-level verification with synthetic data only. It is not evidence that the method is valid for any particular real-world research corpus.
