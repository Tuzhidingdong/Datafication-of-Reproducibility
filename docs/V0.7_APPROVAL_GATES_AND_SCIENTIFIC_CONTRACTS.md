# V0.7 — Human approval gates and scientific data contracts

## Purpose

V0.7 turns the existing guided G0–G4 workflow into a locally verifiable state machine. Decisions are explicit events in a JSON Lines ledger. Every event binds named artifacts to their absolute paths and SHA-256 digests, includes the immediately preceding gate event hash, and links to the preceding event in the ledger-wide hash chain.

This is a reproducibility and workflow-integrity mechanism, not user authentication. The reviewer identifier is declared by the operator and is not independently authenticated. The ledger detects ordinary file edits, event edits, broken history, stale artifacts, and upstream approval changes; it is not a tamper-proof signature system against a person who can rewrite the entire ledger and recompute every hash.

## Gate meanings and required artifacts

| Gate | Scientific decision | Required artifact IDs |
|---|---|---|
| G0 | Confirm research scope and the source inventory | \`dataset_manifest\`, \`source_inventory\` |
| G1 | Approve source-to-canonical mappings and entity grouping | \`mapping_plan\`, \`mapping_validation\`, \`source_inventory\`, \`build_spec\` |
| G2 | Approve canonical data/reconciliation state and the endpoint-specific analysis task | \`canonical_bundle\`, \`canonical_validation_report\`, \`reconciliation_report\`, \`modeling_task\` |
| G3 | Select zero or one interaction candidate for deeper scientific interpretation | \`interaction_report\`, \`interaction_manifest\`, \`robustness_report\`, \`robustness_manifest\`, \`interaction_selection\`; if one is selected, also \`mechanism_plan\` |
| G4 | Approve the exact publication package plan and reviewed result scope | \`publication_plan\` plus at least one reviewed result artifact |

G4's reviewed-result artifact ID must be one of: \`model_report\`, \`reproducibility_report\`, \`interaction_report\`, \`mechanism_findings\`, or \`virtual_prediction\`.

A single G3 decision packet selects at most one interaction because the current mechanism-plan contract describes one interaction ID. If no candidate is selected, G3 can be approved without a mechanism plan; mechanism analysis remains unavailable.

The gate record also requires a non-empty reviewer identifier and rationale. A \`REVISE\` or \`STOP\` event is retained in the ledger and blocks all subsequent gates. Silence, a successful Python command, a passing schema, or an Agent's generated text never creates an approval event.

## Commands

After explicit user approval of the scope and audit artifacts, record G0:

\`\`\`bash
dor gate-record --workflow-ledger workflow_gate_ledger.jsonl --gate G0 --decision APPROVE --reviewer "human-reviewer" --rationale "Reviewed research scope and source inventory." --artifact dataset_manifest=01_audit/dataset_manifest.json --artifact source_inventory=01_audit/source_inventory.json
\`\`\`

After reviewing the exact mapping and build specification, record G1:

\`\`\`bash
dor gate-record --workflow-ledger workflow_gate_ledger.jsonl --gate G1 --decision APPROVE --reviewer "human-reviewer" --rationale "Approved explicit source mappings and grouping grain." --artifact mapping_plan=mapping_plan.json --artifact mapping_validation=mapping_validation.json --artifact source_inventory=01_audit/source_inventory.json --artifact build_spec=canonical_build_spec.json --artifact build_spec_validation=build_spec_validation.json
\`\`\`

G2 is recorded after canonical construction, integrity validation, reconciliation, and task preparation:

\`\`\`bash
dor gate-record --workflow-ledger workflow_gate_ledger.jsonl --gate G2 --decision APPROVE --reviewer "human-reviewer" --rationale "Approved the exact canonical data, reconciliation state, endpoint, features, and split design." --artifact canonical_bundle=02_canonical/canonical_bundle.json --artifact canonical_validation_report=02_canonical/canonical_validation_report.json --artifact reconciliation_report=03_reconciliation/reconciliation_report.json --artifact modeling_task=modeling_task.json
\`\`\`

G3 requires a human interaction-selection record conforming to \`schemas/interaction_selection.schema.json\` version 1.1. It must classify every interaction ID exactly once, select at most one candidate, and bind the exact interaction-report and robustness-report SHA-256 hashes. The approval packet binds both report/manifest pairs. Runtime checks verify that the interaction and robustness manifests point to the exact approved G2 modeling_task hash and share the same cohort, cohort-report, split-manifest, and cohort-manifest hashes. A selected candidate requires a mechanism plan with matching task and interaction IDs.

\`\`\`bash
dor gate-record --workflow-ledger workflow_gate_ledger.jsonl --gate G3 --decision APPROVE --reviewer "human-reviewer" --rationale "Selected this candidate after reviewing support, robustness, Study coverage, and counterexamples." --artifact interaction_report=04_modeling/interactions/interaction_discovery_report.json --artifact interaction_manifest=04_modeling/interactions/interaction_discovery_manifest.json --artifact robustness_report=04_modeling/interaction_robustness/interaction_robustness_report.json --artifact robustness_manifest=04_modeling/interaction_robustness/interaction_robustness_manifest.json --artifact interaction_selection=interaction_selection.json --artifact mechanism_plan=mechanism_plan.json
\`\`\`

When no candidate is selected, omit \`mechanism_plan\`; mechanism analysis will remain unavailable.

G4 binds the final package plan and at least one reviewed result artifact:

\`\`\`bash
dor gate-record --workflow-ledger workflow_gate_ledger.jsonl --gate G4 --decision APPROVE --reviewer "human-reviewer" --rationale "Approved this exact deliverables scope with the recorded limitations." --artifact publication_plan=publication_package_plan.json --artifact model_report=04_modeling/baseline_run/model_report.json
\`\`\`

Inspect gate state:

\`\`\`bash
dor gate-status --workflow-ledger workflow_gate_ledger.jsonl
\`\`\`

Every artifact path is resolved and hashed when the event is recorded. Gate status re-hashes files. A changed/missing artifact becomes \`STALE_ARTIFACT\`; changing an upstream gate decision makes downstream decisions \`BLOCKED_UPSTREAM\`. Re-approve the affected gate and then re-record downstream gates in order. History is append-only; old decisions are not overwritten.

## CLI enforcement

The following commands require current approvals:

- G1: \`build-canonical\`
- G2: \`build-cohort\`, baseline fitting, nested reproducibility evaluation, interaction discovery/robustness, and virtual condition prediction
- G3: response-surface generation and mechanism evidence bridge
- G4: publication package assembly

The commands validate all earlier approvals too. They check exact directly supplied artifact paths where applicable. The response-surface command verifies that its interaction ID was selected in the current G3 packet. The mechanism bridge additionally verifies that its plan is the exact plan bound at G3 and that its interaction ID was selected.

For backward compatibility with archived pre-V0.7 scripts only, gated commands expose \`--allow-untracked-legacy\`. Never use this override in a real project. The Skill does not use it. Omitting both a ledger and the explicit legacy override fails closed.

## Scientific grain diagnostics

Cohort reports include non-destructive grain diagnostics:

- Multiple Conditions with the same \`condition_type\` in one Experiment are flagged; no condition is selected, averaged, or collapsed.
- Repeated Observations with the same Experiment/target/exact endpoint are flagged when explicit identity is missing.
- Supplied \`replicate_id\`, \`replicate_group_id\`, \`sample_id\`, \`specimen_id\`, \`measurement_id\`, and \`technical_replicate_id\` values are reported, but their meaning and independence are not inferred.
- Every Observation remains a separate record. Study remains the outer validation group. No duplicate row is silently converted into a replicate or independent sample.

The canonical validator continues to enforce Experiment–Study–System–Condition referential consistency. The cohort builder continues to require exact target/endpoint definitions, exact units, reported scalar values, unique feature bindings, and exactly one matching linked Condition for every selected feature/Observation.

## Acceptance boundary

V0.7 uses synthetic files only. Tests cover gate ordering, missing artifacts, stale file hashes, changed upstream approvals, ledger tampering, G3 selection/report hash integrity, exact CLI bindings, ambiguous Condition grain, and repeated Observations without inferred replicate identity. These tests establish runtime enforcement and diagnostics; they do not prove real scientific mapping correctness. No project-specific real research corpus is loaded; full scientific acceptance remains reserved for V1.0.


\`REVISE\` and \`STOP\` events may be recorded without artifacts when a full approval packet is not available. \`APPROVE\` events require the complete gate-specific artifact set. A STOP decision at G0 is therefore recordable before any audit files exist.


## V0.8 — Cross-artifact lineage and fully approved end-to-end acceptance

The approval event now checks cross-artifact consistency before it is appended:

- G1 re-runs deterministic mapping validation from the bound mapping_plan and source_inventory, then re-runs the standalone Build Spec validator against the exact mapping plan, inventory, and build spec. It requires the G1 source inventory path and hash to match G0, the mapping plan and build specification to reference that exact inventory, and the build specification to reference the exact mapping-plan hash/version. Entity source files and formats, grouping selectors, mapping-rule compatibility, and relationship declarations are checked before approval; no source records are read and no Canonical Bundle is built by this validation command.
- G2 requires a passing canonical-validation report, a reconciliation report whose bundle_sha256 matches the exact canonical_bundle, and canonical build_provenance hashes matching the currently approved G1 mapping_plan, source_inventory, and build_spec.
- G3 binds interaction and repeated-seed robustness report/manifest pairs. Both manifests must reference the exact G2-approved modeling_task hash and the same cohort CSV, cohort report, split manifest, and cohort manifest hashes. Their report output hashes must match the bound reports, and both reports must have the same candidate ID set. The G3 selection record is schema version 1.1 and binds both report hashes.
- Existing file-hash checks still invalidate a changed/missing artifact; upstream decision hash changes still block every later gate.

The synthetic end-to-end test now executes all five gates with actual \`dor gate-record\` and supplies \`--workflow-ledger\` to every gated operation. It does not use \`--allow-untracked-legacy\`. Negative tests append a revised, internally consistent G1 event and verify that existing G2–G4 approvals become blocked, and pass a substituted Canonical Bundle to \`dor build-cohort\` to verify rejection before an output directory is created.

This remains a simulated synthetic reviewer flow. It validates deterministic approval-state enforcement and artifact lineage, not human authentication, scientific correctness, or any project-specific real research corpus.
