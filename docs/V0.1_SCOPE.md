# V0.1 scope and acceptance criteria

## In scope

- Antigravity Workspace Skill entry point.
- Domain-neutral methodology and architecture references.
- Reusable domain-profile template.
- An external adapter and project-owned profile boundary, with no built-in subject-area mappings.
- Project, Worker task/result, phase-state, finding, and publication-manifest schemas.
- Read-only CSV/JSON structural audit using Python standard library.
- Source hashing and source-change checks during audit.
- Separate derived output directory.
- Guided approval gates and Worker task/result protocol.
- Publication package navigation requirements for a downstream Writing Skill.
- Unit tests for audit behavior and source preservation.

## Explicitly out of scope for V0.1

- Automatic semantic mapping of project-specific fields before source structure and meaning are reviewed.
- Building a canonical scientific database from an unverified nested JSON schema.
- Automatic matching of all systems/comparisons.
- Missing-value imputation.
- Any machine-learning model training.
- Automated interaction discovery.
- Mechanism claims.
- DFT/AIMD/MD execution.
- Full publication-package generation from real analysis results.
- Direct integration with manager-specific MCP methods.

## Acceptance criteria

1. Antigravity recognizes the Skill from the repository workspace location.
2. Skill frontmatter contains a valid name and clear description.
3. The Skill respects G0-G4 approvals and preserve-mode source policy.
4. The project schema validates a valid project config and rejects invalid required fields.
5. The local audit can inspect CSV and JSON without modifying them.
6. The audit writes outputs only to a separate run directory.
7. Source hashes before and after inspection match.
8. CSV audit reports row count, header fields, non-empty counts, coverage, and coarse type hints.
9. JSON audit validates parseability and reports top-level structure without pretending that semantic mapping is complete.
10. Tests verify normal audit, source immutability, invalid JSON handling, and unsafe output-path rejection.
11. Worker task/result contracts are machine-readable and manager-neutral.
12. Publication package specification requires both README_FOR_WRITING_SKILL.md and package_manifest.json.
13. All project-specific semantic mappings remain external and require review against their exact source files.
14. No private datasets, papers, tokens, or local machine paths are committed.

## V0.1 completion evidence

A V0.1 run must generate a data audit report and dataset manifest. A human must review the actual source structure and approve the G1 gate before canonicalization or modelling begins.
